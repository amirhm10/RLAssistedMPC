# Distillation wrapper: Aspen COM method lookup compatibility

The author reported that batch `20261014_151602_5a780b` failed all ten horizon repetitions before training and recalled the pywin32 bad-context workaround. Inspection confirmed the same first error in every worker: accessing `self.ad.openDocument` triggered a property-get COM invocation without the filename and Aspen returned HRESULT `-2147352567` (`DISP_E_EXCEPTION`) with "A string value was expected". The same lookup error affected `CloseDocument` during cleanup. No repetition had completed.

The installed `win32com.client.dynamic` classifies a probed member as a method only for HRESULTs in `ERRORS_BAD_CONTEXT`; this list does not contain Aspen's generic exception code. The behavior was checked against the installed source and the [upstream pywin32 source](https://github.com/mhammond/pywin32/blob/main/com/win32com/client/dynamic.py).

Added a worker-local `aspen_com_compatibility` context in `run_distillation_phase2_repeats.py`. It temporarily includes `DISP_E_EXCEPTION` in that list around experiment execution and Aspen cleanup, then restores the original list. This covers nested Aspen COM objects without changing library files, method arguments, simulation/controller/learning settings, file assignments, or scheduling. Errors from the actual method invocation continue to propagate. Replication metadata records the compatibility workaround.

Added regression tests using the real installed pywin32 `CDispatch` with a synthetic COM backend. They reproduce the precise lookup failure, verify that the patched lookup calls `openDocument` with the filename and `CloseDocument` with the original argument, preserve genuine method failures, and restore both previously patched and unpatched contexts. All 20 focused wrapper checks passed, including ten-way process overlap, unique files/snapshots, combined parity, failure/resume, and cleanup. No Aspen session or training was launched during verification.

Files inspected: all ten failed horizon logs, the failed manifest/status, root `AGENTS.md`, the wrapper and focused tests, `systems/distillation/plant.py`, the installed pywin32 `dynamic.py`/method builder, and the upstream dispatch source. Files changed: the wrapper, focused tests, usage guide, and this note. The failed batch and installed library are preserved. A new batch is required because the wrapper source hash changed; the old manifest is not rewritten to bypass provenance checks.
